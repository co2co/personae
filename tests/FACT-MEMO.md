# 技术备忘·事实保全机制（v0.17.0 已移除，设计存档待复装）

> **本文档的用途**：事实保全（常量层）机制曾于 v0.12-v0.16 期间实装，因在当前架构下**与 history 高度冗余**而于 v0.17.0 整体移除。本文档保存其完整设计与实测数据，供两种场景查阅后**照此复装**：
> 1. 上下文规模逼近容量边界（实测 tok 峰值已达 15240，模型 n_ctx=131072，尚未触线）；
> 2. 实测出现「早期事实被遗忘导致叙事漂移」的现象（当时未观测到该现象）。
>
> 复装时无需重新发明：设计、判据、代码骨架、测试用例、踩过的坑都在本文。

---

## 一、设计初衷与真实作用

### 初衷（v0.12.0 提出）

长篇推演中，LLM 会「漂移」：已死的角色重新出现、已毁的物件复原、已建立的设定被改写。事实表的目标是给模型一份**不可违背的清单**，在 system 块里常驻，压制漂移。

### 实际定位（重要，与初衷有偏差）

它**不是**记忆机制的补充，而是**纪律机制**：

- **history 负责「记住」**——正文原文在上下文里，模型自然记得。80 轮实测：轮距 3（窗口内）召回 10/12，轮距 38（压缩区）召回 10/12，**两段无差异**。
- **facts 表负责「不许违反」**——即使模型记得，它也可能为了剧情需要「忘记」。事实表用 `[既定事实（不可违背）]` 块在 system 中段（primacy 位置）压制这种倾向。

**这个偏差导致它在能力上与 history 高度冗余**：它记录的内容，正文里本来就写过一遍。实测抽样（会话 3e19589c，10 条事实对同一会话叙事原文做关键词匹配）：

| 事实条目 | 关键词在 history 命中 |
|---|---|
| 沈川低声自语'活着真好' | 3/3 |
| 苏青在门外声称自己腿被咬或抓伤 | 2/4 |
| 沈川拉开入户门 | 0/2 |
| 苏青自称是护士 | 0/2 |

## 二、移除前的实测数据（决定移除的依据）

### 数据一：facts 表在抄正文，导致膨胀

| 数据源 | 轮数 | facts 总数 | 其中 core 类 |
|---|---|---|---|
| 80 轮长上下文压测 | 80 | 26 | **0** |
| 会话 3e19589c | 7 | 10 | 1 |
| 会话 557af4b0 | 0 | 16 | 0 |

80 轮的 26 条里，**没有一条 death / disable / destroy**——全是 deed/utterance 类的剧情动作记录。原始构成：`utterance` 4 条、`deed` 3 条、`identity` 1 条（另一会话 16 条里 15 条是 event 类）。

**它把每个回合的剧情动作都记了一遍**，这是噪音不是保险。

### 数据二：核心用途从未被验证

- **80 轮压测里一个角色都没真死过**。用精确模式（没了气息/咽气/当场死亡/断气/停止呼吸）全 80 轮扫描 → **0 命中**。（注：早期统计「71/80 轮含死字」是误判，全是「死死」「死寂」这类修饰词。）
- 因此「已死角色复活」这一**最初设想的目标场景**从未被触发过。

### 数据三：噪声占比过高

以会话 557af4b0 的 15 条 event 类为例，存在明显重复上报：

```
R4 沈川同意给予三分钟观察时间…
R6 沈川设定了十分钟的观察期限…
R7 沈川宣布给予周子航第二个十分钟观察期…
```

这三条各有环境变化、**都是有效常量**，但说明纪官对「同一决定的不同拍板」缺少分辨。逐字去重拦不住这类同义改写。

### 数据四：容量尚未触线

- 80 轮实测 prompt_tok：R1=3685 → R20 峰值 15240 → R80 14200
- 模型 `n_ctx = 131072`（Qwen3.8-27B，llama.cpp）
- 结论：**占模型容量约 12%，远未到边界。** facts 表设计的适用前提（history 装不下）尚未成立。

## 三、机制完整设计（复装时照此实现）

### 3.1 数据结构

```python
# 快照字段（memory.new 初始化）
"facts": [],   # 常量层：只增不改的不可逆事实

# 单条结构
{
    "kind": "death|disable|destroy|identity|deed|utterance|other",
    "subject": "对象（角色名或物件名）",
    "text": "一句话事实",
    "evidence": "本轮叙事原文片段（逐字照抄，用于举证核验）",
    "round": 8,
    "invalid": False,   # 作者手动作废后置 True，条目留痕但不注入
    "reason": "",        # 作废理由
    "folded": False,     # 折叠产生的摘要行标记
}
```

### 3.2 分类定义

```python
FACT_CORE_KINDS  = {"death", "disable", "destroy", "identity"}   # 天然常量
FACT_EVENT_KINDS = {"deed", "utterance", "other"}               # 需严格判据
FACT_CAPS        = {"core": 30, "event": 8}                      # 折叠上限
```

- **core**（death/disable/destroy/identity）：死亡、永久致残（失明失聪疤痕）、物件彻底销毁、身份类事实。
- **event**（deed/utterance/other）：**当众说出、且改变了局面的**具体事。

### 3.3 判据（v0.16.0 收窄后的最终版，这是关键）

**核心区分**：不是「说出口了」，而是「说出来之后，有什么变得不一样了」。

**event 类只填三类**：
1. **关系定性被当众宣布**：结盟 / 决裂 / 认亲 / 当面翻脸 / 承认敌对
2. **背叛与投靠**：临阵倒戈、向敌方透露情报、当众撇清关系
3. **不可撤回的宣告**：当场交出东西、毁掉东西、宣布退出

**event 类一律不填**：
- 一次性动作（拉开门、递东西、起身、看向某处、消毒、搜查）
- 内心独白与自言自语（「活着真好」这类情绪流露）
- 提议、商量、询问（「我们是不是该走？」——尚未拍板就不算事实）
- 同一决定的重复上报
- 解读与推测（「她像是怕人发现床底下的东西」——text 只写事实，不写推论）

**总判据**：能被后续一个动作改掉的就不是常量。
- 门被封死、路被堵、断电 → 可被爆破/打开/修复，**不算**
- 人离开 → 还会回来，**不算**
- 物品在谁手上 → 可被偷抢转送，**不算**
- 受伤 → 可治愈，**不算**
- 口头承诺尚未兑现 → 可被履行勾销，**不算**
- 提出动议 → 可被否决，**不算**
- 关系好坏、态度、天气时间场景 → 填 `state_updates`，**不算**

### 3.4 举证核验（防幻觉的核心纪律）

引擎不猜，**只核验纪官上报的内容是否逐字出现在正文里**：

```python
EVIDENCE_MIN_LEN = 4   # 只挡「一两个字碰巧命中」的伪举证
                      # 不要设更高：压测实证纪官会举证「没有脉搏。」（5 字）

def _evidence_ok(evidence, reply):
    """evidence 必须逐字出现在本轮叙事中，不通过则丢弃该条目。"""
    ev = (evidence or "").strip()
    return bool(ev) and len(ev) >= EVIDENCE_MIN_LEN and ev in reply
```

**不通过的条目会留 logger 警告**（不静默丢弃——压测中「线索明明出现却没归档」难以定位，就是静默丢弃造成的）。

### 3.5 折叠机制

条目超过 `FACT_CAPS` 时，把最老的同类折叠成一行摘要：

```python
# 已折叠条目不再是折叠对象（否则会套娃：R1-R3 摘要里又生出 R1-R1 摘要）
# 摘要行每组唯一，只更新回合区间与对象名单，不重复拼接正文
```

### 3.6 注入位置

`prompter.build_session` 中，位置在 system 块中段（primacy 位置，优于 recency）：

```python
fact_lines = ["- " + f["text"] for f in snap["facts"] if not f.get("invalid")]
if fact_lines:
    blocks.append(
        "[既定事实（不可违背）]\n" + "\n".join(fact_lines)
        + "\n以上为推演中已经确立、且在本世界观下不可逆转的事实，严禁写出与之矛盾的内容。"
          "已登记死亡者不得再有台词、动作或内心活动，只能被他人提及或回忆。"
    )
```

**关键**：`compress_history` 会把 history 压成骨架，而 facts 块**不参与压缩、常驻 system**——这是它存在的根本理由（history 装不下时它是唯一不丢的锚点）。

### 3.7 矛盾自检

```python
def check_fact_conflicts(snap, reply):
    """正文与常量矛盾时告警（只报不改——纠错权归作者）。"""
    dead = [f["subject"] for f in snap["facts"]
            if f["kind"] == "death" and not f.get("invalid")]
    # 只做代价最低、误报可控的一类：已登记死亡者又作为说话人登场
    # 回忆、被提及不算矛盾 → 按「名字开口」（行首「名字：」）判，不按「名字出现」判
```

### 3.8 作者纠错通道

`POST /api/fact/invalidate` → `director.invalidate_fact()`：把条目 `invalid=True` 并记录理由，条目留痕（避免下一轮被纪官重新抽回），前端显示「已作废」并可划线显示。

### 3.9 前端展示（v0.16.0 最终版）

```javascript
const FACT_PREVIEW = 5;   // 只展示最近 5 条
// 排序：有效的在前（回合倒序）→ 已作废的在后
// 超出显示「展开更多（另有 N 条更早的）」，状态存 window.__factsExpanded
```

## 五、踩过的坑（复装时务必避开）

### 5.1 不要用代码层词表做语义降噪

v0.16.0 曾尝试在 `add_facts` 里加代码级降噪：
- `_fact_is_low_value()`：情绪/独白词表
- `_fact_near_duplicate()`：动词重叠去重

**结果：会误杀有效事实，已撤回。**

- 中文 Jaccard 字符相似度对同义句只有 **0.27**（「故意划伤伤口边缘」vs「划伤以观察感染速度」是同一件事），阈值无从下手。
- 换成动词重叠后，把「同意三分钟→改十分钟→再延十分钟」这类**同一决定的三次拍板**全部合并——但那三次各有环境变化，都是有效常量。
- 词表匹配在中文上本质脆弱：漏「拉开了入户门」、误伤「林小满当众质问…眼神…」。

**教训：这类语义判定只能靠提示词约束模型，代码层不要用词表硬拦。**

### 5.2 自称消解要用「我叫」不能用「我是」

同期 aux 群演登记踩的坑（相关但不同模块）：「苏青：（喘息）我是护士」里的「我是护士」报的是**身份**不是姓名，若把「我是」当自称判据会把「苏青」误当成泛称消解掉。

### 5.3 举证长度下限不要设高

`EVIDENCE_MIN_LEN` 从 8 压到 4。早前设 8 会把「没有脉搏。」（5 字、逐字出现在正文）这类真实短句误杀。

## 六、结论存档

**移除理由**（v0.17.0）：在当前容量边界内，facts 表与 history 高度冗余，代价（抄正文、占 prompt、条目膨胀、前端折叠）大于收益（一条未被验证的保险）。

**保留理由**（供将来）：它是 history 装不下之后唯一不参与压缩的锚点。届时复装，本文档即实现规格。
