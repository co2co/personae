# 世界书使用说明书（Lorebook）

> 适用版本：群像弈（Personae）【暂定】精简版沙盘（原创 Python/Flask 多角色关系推演引擎）。
> 本文档面向**创作者**：告诉你世界书怎么用、每个字段干什么、什么时候该用什么，并附可直接照抄的例子。

---

## 一、世界书是什么

世界书（Lorebook）是一份"**按需投放的背景设定库**"。

普通做法是把所有设定一股脑塞进提示词，又长又费 token，还容易让模型搞混。世界书的思路是：**只有"当前剧情/对话涉及到的设定"才会被注入给模型**。你为每条设定写几个触发词，模型读到相关情节时，这条设定才出现。

一句话：**提到什么，补什么。**

在本引擎里，世界书同时承担两种职责：

| 类型 | 作用 | 是否注入提示词 |
|---|---|---|
| **设定条目** | 世界观、地点、规则、人物背景等背景信息 | 命中后注入 |
| **秘密条目** | 某角色的隐秘（把柄、身份伪装、身体秘密等） | **不注入**；开局 seed 进该角色秘密表，按"暴露逻辑"逐步揭开 |

## 二、怎么打开编辑器

1. 启动服务：`python app.py`，浏览器打开 `http://127.0.0.1:5000`
2. 点顶栏 **「世界书」** 按钮 → 打开世界书管理面板。
3. 面板顶部是一个下拉框（已有世界列表）+ 四个按钮：
   - **+ 新建世界**：输入世界名（建议英文/拼音，作文件名）。
   - **删除世界**：删整份设定与秘密（若仍有角色卡绑定，会二次确认后强制删除）。
   - **+ 新增条目**：在列表中加一条空白条目（默认展开）。
   - **保存整份**：把当前所有条目整份覆盖写入 `data/worlds/<名>.json`。**务必点保存，否则改动不落地。**
4. 下方有"命中预览"框，用来测试触发词是否按预期 fire（见第六节）。

> 世界书是"整份覆盖保存"——编辑完点一次「保存整份」即可，不需要逐条保存。

## 三、条目的基本结构

每条世界书条目由一组字段组成。展开任意条目可看到：

```
┌─ [⠿拖拽] [▾展开] 顺序 1  [秘密]  条目摘要  [✔启用] [▢秘密条目] [删除条目]
│
└─ 触发词 keys：魔法学院、学院
   设定正文 content：
   城西的魔法学院是大陆最高学府，入学者需通过天赋测验……
   ── 高级选项 ──
   [▢ 常量条目]   插入位置 position：[before ▾]   扫描深度 depth：[    ]
   ── 秘密专属（勾选秘密条目才出现）──
   秘密归属角色 character：[林梦雅]
   bottom_line（暴露底线）：[……]
```

字段分三类：**必填基础**（keys、content）、**开关**（启用、秘密条目）、**高级选项**（常量/位置/深度）。

## 四、字段逐个讲解（含例子）

### 1. 触发词 `keys` ⭐ 核心

一组关键词，用**逗号、顿号或空格**分隔。当前剧情/对话（含你注入的导演指令）里**出现任一关键词**，这条设定就命中。

> 匹配是"包含"判断，不要求整词。关键词建议用作品的**专有名词**，越独特越精准，避免用"她""走"这类泛词误触发。

**例子**：设定"镇内禁令"，触发词写 `禁用、违禁、处罚`。则只要某轮对话或指令里出现"私斗"，这条就注入。

### 2. 设定正文 `content` ⭐ 核心

命中后要注入给模型的设定内容。写清楚、写具体，模型才会据此推演。

**例子**：
```
content：本镇严禁携带武器，违者当场没收并逐出城门。任何冲突都必须走镇务所仲裁，
私斗一律重罚，不接受"私了"。
```

### 3. 启用 `enabled`

取消勾选 = 该条目暂时停用（不参与命中、不注入）。适合"先写着、以后再用"或临时屏蔽某条。

### 4. 优先级 / 排序（拖拽 ⠿）

- 条目**自上而下 = 优先级从高到低**。顶部条目优先级最高。
- 系统按 `优先级 = 100 - 序号×5` 计算（第 1 条=100，第 2 条=95……）。
- 当命中的条目**超过 8 条**（`max_entries=8` 硬上限），只注入优先级最高的 8 条，其余**静默丢弃、无提示**。

> 实操建议：把"最该被先看到"的设定（高优先级常量/核心规则）放顶部；把可有可无的补充设定放底部，避免挤掉重要条目。

**例子**：你写了 12 条设定，某一轮剧情同时触发了其中 9 条。系统只注入排名前 8 的，第 9 条被丢弃——而你可能以为它进去了。所以：**别让可能同时命中的条目超过 8 条**，或把关键条目用常量/高排序顶住。

> **秘密条目不占配额**（v0.16.0 起）：勾了「秘密条目」的条目**不进入提示词**，所以它**不参与上面 8 条的竞争**——不会把真正要注入的设定挤掉。秘密仍然会在编辑器命中预览里显示（带「秘密」标签），只是不进 prompt。

#### 设定条目太多怎么办（`max_entries=8` 装不下时）

8 条只是默认值，不是硬性限制的终点。但**放宽它有真实代价**：注入进提示词的设定越多，每一条被模型注意到得越轻。判断该不该放宽，看的是**设定总字数**，不是条目条数。

实测参考（30 条世界书、关键词极宽导致全部命中的最坏情况）：

| 实际注入条数 | 设定字数 | 提示词总量 | 叠加 8 轮对话后 |
|---|---|---|---|
| 8 | 约 1150 字 | 约 35% | 约 75% |
| 12 | 约 1750 字 | 约 41% | 约 81% |
| 16 | 约 2300 字 | 约 46% | 约 87% |
| 20 | 约 3000 字 | 约 53% | 约 93% |
| 30 | 约 4500 字 | 约 67% | 越线 |

**四条建议**：

1. **先压条目，再谈放宽**。一条写清楚胜过三条各写半句——把啰嗦的设定合并、删掉重复描述，通常比放宽上限更有效。
2. **一次最多 +4 条**（8 → 12），别一次跳到 20 以上。放宽的收益是「该设定被看到」，代价是「所有设定都被稀释」，后者伤的是每一条。
3. **超过 30 条就拆世界**。角色卡的 `world` 字段决定开局加载哪份世界书——把设定按主题拆成多份、按场景切换，比放宽单世界上限更能让模型聚焦。
4. **放宽后要实测**。别只看注入量：跑一轮压测，确认「点名角色出场率」「秘密翻转」「回复长度趋势」三项都没退化再放心。

> **为什么世界书不会随对话变长而膨胀**：提示词里只保留最近 8 轮对话原文，更早的回合压成简短摘要块。所以世界书的注入量是**每轮恒定**的，与这局已经聊了多久无关。

### 5. 常量条目 `constant` 🔑 重点

勾选后：**不依赖任何关键词，每一轮都必注入**。用来放"必须永远在场的基础规则"。

- 常量条目无视 `keys` 与 `depth`。
- 是解决"长文里基础设定掉线"的关键武器：普通条目只回看最近几轮聊天，聊远了就不命中；常量条目永久在线。

**例子**：
```
[常量] 镇内禁令：私斗一律重罚，冲突须走镇务所仲裁。
[常量] 处境总则：五人被困城郊仓库，卷帘门紧闭，门外有人反复敲门试探，补给见底。
```
这两条勾了常量，无论聊到哪、隔多少轮，模型始终把"禁令+被困"当铁背景，不会写出"主角轻松绕过禁令"这种崩设定剧情。

### 6. 插入位置 `position` 🔑 重点

决定命中设定**插在提示词的哪个位置**，影响"谁该看到、何时看到"。

| 值 | 命中后落在哪 | 注意力位 | 实质作用 |
|---|---|---|---|
| `before`（默认） | 系统层首条消息顶部（`messages[0]` 顶部），在对话历史**之前** | primacy（首部强） | 当"背景框架"——角色带着这副眼镜解读整个世界；**定调但不催行** |
| `after` | 末尾 user 消息（`【导演指令】`之后），在对话历史**之后、生成点之前**的最后一瞥 | recency（尾部最强） | 当"临门一脚"——模型生成前最后看到它，最容易变成"此刻该做什么"的推力，**直接催角色当下行动** |

> **一句话核心**：`after` = 触发即**临门一脚、催角色当下行动**；`before` = 触发即**背景滤镜、给场景定调但不催行**。
>
> 机制来源：transformer 的 U 形注意力——消息首部（primacy）与尾部（recency）权重最高。`before` 占首部、`after` 占尾部，所以两者即便都"命中才注入"，对角色行为的拉扯方式也不同：一个定调、一个催促。

**为什么这重要**：`position` 只决定"命中后，它以哪种权重影响下一句"，**绝不改变"角色是否看得到"**（那是 `constant` 的职责）。把"角色不该知道的上帝视角 / 元设定"写进世界书本身就会 OOC——这是**内容权限**问题，位置解决不了。另外，该差异对短条目是**真实但幅度温和**的、且随模型而变，别指望设了 `after` 角色就判若两人。

**例子**：
```
[after] 当下威胁：门外的人已聚到数十位，通风口反复有撬动声，是今日最大隐患。
```
这条设 `after`——只有某轮提到"门外/撬锁/通风口"时才作为"当前环境"拼在生成点前最后一瞥，直接催角色对门外威胁作出反应；不会被当成远古背景框架。

### 7. 扫描深度 `depth` 🔑 重点

控制这条设定**只回看最近多少轮聊天**来匹配关键词。

- 留空 = 用全局默认 `4`（回看最近 4 条聊天）。
- 填数字（如 `10`）= 该条目回看最近 N 条。
- 窗口 = 最近 N 条聊天 **+ 你本轮注入的导演指令**（指令也参与匹配）。
- 若 depth ≥ 已有聊天总数（或达到 60 轮扫描窗口上限），则回看全部；depth 在 1~60 间精确生效，超过 60 等同 60。

**用途**：默认 4 条意味着"第 5 轮提过的事，隔 4 轮后就不再触发"。如果你的设定需要"远距离仍能命中"，就调大 depth。

**例子**（`depth=10`）：
```
keys：城东、集散地、商队
content：城东废弃体育馆被传改成了临时集散地，有物资有活人，但路途凶险。
depth：10
```
第 1 轮提了"城东还有希望"，之后 5 轮都在聊别的。默认 depth=4 会丢失这条；设 `depth=10` 后，第 6~10 轮仍命中——角色不会突然"忘了城东还有生路"。

#### 7.1 决策表：constant / position / depth 怎么选

`constant`（注入条件）与 `position`（注入位置）是**两个独立维度**，和 `depth` 搭配出四种合法组合。选错组合是"设定总掉线 / 总被忘"的头号原因：

| 设定性质 | constant | position | depth | 理由 |
|---|---|---|---|---|
| 铁共识 / 世界观法则（尸变不可逆、全员幸存者互不熟） | **true** | before | 无关 | 每轮必注入系统层，永不褪色——真"共识"的家 |
| 永久据点背景（便利店后仓） | **true** | before | 无关 | 同上，永久在场 |
| 话题型共享知识（"地铁通道诡异"，只在聊地铁时相关） | false | before | 偏深 8~15 | 关键词离场后仍能暖场多轮；想更耐久就调更高 |
| 一过性共享细节（某句气话、临时约定） | false | after | 浅 1~4 | 话题一冷就淡出，不占 prompt |

**关键澄清**：`position=before` 不等于"永久背景"——它只决定*注入时*坐在系统层，**仍只在关键词命中时才注入**；真正"每轮都在、永不褪色"的是 `constant=true`（此时 `depth` 完全无效）。所以：

- **真正不容褪色的铁共识 / 永久据点 → 直接 `constant=true`，不要靠调深 `depth` 来"防忘"。**
- `constant=false, position=before` 严格说是"当成背景框架呈现的**话题型**共享知识"：话题冷却超过 `depth` 轮后就会淡出（最深 60 轮封顶）。若你担心"常识被忘"，那它本质上就不该是 `constant=false`，该升常量。
- 注意：从"剧本 / LLM 导入"世界书时，`script_refiner` 会强制 `constant=true→before`、`constant=false→after`（防自相矛盾组合）；想自由解耦（如 `constant=true, position=after`）只能手动改 JSON。

#### 7.2 常见误区：before/after 不是"从开局常驻的记忆"

很多玩家（包括从酒馆迁移过来的）会卡在这里：以为设了 `before` 或 `after`，这条设定就从游戏开局一直在角色视野里，能随时当决策参考。这是错的，也是"设定总被忘 / 角色不按设定行动"的头号根源。

**核心心智模型：世界书条目只有两种命**

1. **常量条目（`constant=true`）**——每轮必注入，是真正的"记忆库 / 决策地基"。永久事实（地理锚点、世界观法则、铁共识）放这里。
2. **非常量条目（`constant=false`，无论 `before` 还是 `after`）**——只是"话题触发器"。只有当它的关键词在最近 `depth` 轮聊天里被提及时，才注入那一两轮；话题冷却超过 `depth`，它就不在了，模型不会主动想起。

**before / after 是"注入到哪、以哪种权重影响下一句"的标签，不决定"是否常驻"**

- `before`：命中后并入系统层首条消息顶部，当"背景框架"呈现——**触发即背景滤镜、给场景定调但不催行**。
- `after`：命中后并入末尾 user 消息（生成点前最后一瞥），当"临门一脚"呈现——**触发即催角色当下行动**。这是与 before 的实质性差别（见第 6 节）。
- 两者对非常量条目**都一样是"命中才注入"**；只有 `constant=true` 才会让条目"每轮都在"。所以"想让设定永远跟着角色"→ 勾常量，不是选 `before`/`after`。

**触发非常量条目的两个入口**

- 叙事自然衍生：角色聊到相关词，关键词命中。
- 玩家注入扰动：玩家在发言 / 环境干扰里刻意带上关键词，主动命中（对应"玩家凭常识注入环境干扰、推动世界运转"的设计）。

**那 depth 该设多少？**

- `depth=4`（默认）是"话题冷却"：提过之后暖 4 轮就淡出，适合一过性细节。
- 重要但偶发的剧情线用深 `depth`（8~15），让它暖更久。
- **但 depth 再大也救不了"关键词从未被提"的时刻**——只有 `constant=true` 能。怕重要事实被忘？升常量，别调深 depth。

> 一句话记牢：**记忆库只有 `constant`；`before`/`after` 只是位置，非常量条目是"关键词命中才闪现的临时参考"，不是开局常驻的记忆。**
>
> 补充一点精确化：非常量条目在"话题正热的 `depth` 轮内"其实是**能**当临时决策参考的（那几轮它就在 prompt 里），只是冷却后不能主动被想起。所以准确说法是"不能当**随时可靠的**抉择参考"，而非完全不能。

### 8. 秘密条目 `secret` + 归属角色 + 底线 🔑 重点

勾选「秘密条目」后，这条**不进入提示词**，而是：

1. 开局时 seed 进**归属角色**的秘密表（快照 `secrets`），初始状态"潜伏"（`known_by` 为空）。
2. 只有剧情里**真的出现"发现动作 + 秘密事实"**（如"角色丙拆开绷带，发现小臂伤痕"），引擎才把它标记为"暴露"，并把知情者写进 `known_by`。
3. 暴露后，该秘密会以"提示"形式注入**相关角色的人设块**（"你的秘密已被 X 知晓，须应对其反应" / "你已知 X 的秘密：……，可据此行动"），驱动后续博弈。

字段：
- **秘密归属角色 `character`**：这条秘密属于谁（owner）。必填——空了不会被 seed 成秘密。
- **bottom_line（暴露底线）**：可选，描述"暴露到什么程度会改写关系/越线"，供模型把握后果烈度。

> 勾选秘密后，上方的高级选项（常量/位置/深度）会自动隐藏——因为秘密不走世界设定注入，这些对它无意义。

**例子**（角色乙的秘密）：
```
[秘密] 归属角色：角色乙
触发词：伤痕、绷带、小臂
content：角色乙三天前弄伤了小臂，自己偷偷包扎隐瞒，怕被当成隐患清掉。
bottom_line：一旦暴露，角色乙会拼命掩盖，团队信任崩塌，可能引发排挤或私逃。
```
开局角色乙的秘密"潜伏"；直到某轮剧情写出"角色丙发现角色乙绷带下的伤痕"，引擎才翻成暴露，并让角色丙据此行动（如借此要挟、或保护性隐瞒）。

### 9. 递归引用 `name` + `#name#` 🔑 重点（进阶）

当一条设定需要**顺带带出相关的另一条设定**时，用递归引用避免手动重复关键词。

机制：
- 给被引用条目起一个 **`name`**（编辑器里"条目名 name"输入框，可选）。
- 在引用方的 `content` 里写 `#条目名#`，例如 `详见 #魔法学院校规#`。
- 一旦引用方被命中注入，引擎会**自动把被引条目也拉进来**（BFS 展开，并防环，不会因互相引用死循环）。
- 被引条目即使自身关键词没命中、也不是常量，也会被拉入——它是"被带着走"的依赖项。

> 递归条目同样受 `max_entries=8` 上限约束：拉入后若总数超限，按优先级保留最高的 8 条。

**例子**（魔法学院世界）：
```
[设定] name：学院
触发词：学院、校舍
content：这是一所古老的魔法学院。校规详见 #校规#。

[设定] name：校规
触发词：（留空也行）
content：学院校规：禁私斗、禁夜出、禁用黑魔法。
```
只提"学院"时，引擎注入"学院"条目，并因 `#校规#` 自动把"校规"条目也带进来——你不必在"校规"上重复填"学院"关键词。

**什么时候用**：世界观有"总纲→分册""地点→该地点规则""家族→家规"这类**从属关系**时最省心。扁平的、互不相关的设定不需要。

## 五、与角色卡的关系

- 角色卡上有 `world` 字段（默认 `home`），决定**这个角色开局加载哪份世界书**。
- 开局时，引擎取"首个在场角色"的 `world` 加载对应世界书（如某剧本角色都设 `world: example`）。
- 世界书里的**秘密条目**会在开局 seed 进对应角色的秘密表（需填 `character`）。

> 提示：删世界书时，若仍有角色卡 `world` 指向它，会先二次确认——避免误删导致角色开局丢失设定。

## 六、命中预览（测试工具）

编辑器底部"命中预览"框：

1. 粘贴一段**模拟的场景/对话文本**（就当是某一轮会发生的事）。
2. 点 **测试命中**。
3. 下方列出会触发的条目：标签显示「设定」或「秘密」，附触发词与正文。

用途：
- 写完后立刻验证"我的触发词到底 fire 没 fire"。
- 常量条目在**任意文本**下都应命中（因为它不看关键词）。
- 秘密条目命中也**只作提醒，不注入 prompt**——红色「秘密」标签提示你这条走的是秘密线。

**例子**：在预览框输入"角色乙小臂的伤痕被角色丙看见了"，点测试 → 应看到角色乙的秘密条目命中（标记秘密），以及任何被"伤痕/绷带"等词命中的设定条目。

## 八、从零建一个世界书（完整走查）

以一份五人被困仓库的剧本为例，从点开编辑器到保存、开局跑通一局，串一遍完整流程。每一步都对应界面上真实的按钮/字段名。

### 步骤 1 · 打开编辑器
- 启动服务：`python app.py` → 浏览器开 `http://127.0.0.1:5000`。
- 顶栏点 **「世界书」**，打开世界书面板。
- 下拉框选已有世界，或点 **「+ 新建世界」** 输入名字（本例用 `example`，建议英文/拼音作文件名）。
- 面板结构一眼看全：

```
下拉[example ▾]  [+ 新建世界] [删除世界] [+ 新增条目] [保存整份]
─────────────────────────────────────────────────
条目列表（可拖 ⠿ 排序、展开 ▸、勾启用/秘密、删除）
─────────────────────────────────────────────────
命中预览框 [测试命中]   命中结果区
```

### 步骤 2 · 先打常量底（必做，防长文掉线）
点 **「+ 新增条目」** 并展开，建两条基础规则：
- 条目 A：`content` 写"本镇严禁携带武器，私斗一律重罚，冲突须走镇务所仲裁"；勾 **常量条目**；`position` 默认 `before`（keys 可留空，常量不看关键词）。
- 条目 B：`content` 写"五人被困城郊仓库，卷帘门紧闭，门外有人反复敲门试探，补给见底"；同样勾 **常量条目**。

> 这两条每轮必注入，模型永远记得"无解药 + 被困"，不会写出崩设定剧情。

### 步骤 3 · 建触发型设定（提到才补）
- 条目 C：`keys` 写 `门外、敲门、通风口、撬锁`；`content` 写"当下威胁：门外的人已聚到数十位，通风口反复有撬动声"；`position` 选 **after**（贴近当下语境）；`depth` 留空（默认 4）。
- 条目 D：`keys` 写 `城东、集散地、商队`；`content` 写"城东废弃体育馆传闻改成了临时集散地，有物资有活人，但路途凶险"；`depth` 填 **10**（远距离仍命中，聊远了也不会忘）。

### 步骤 4 · 埋一条秘密（逐步揭开）
点 **「+ 新增条目」**，勾 **秘密条目** → 自动展开归属字段：
- `character` 填 **角色乙**（归属角色，必填，否则不会被 seed 成秘密）。
- `keys` 写 `伤痕、绷带、小臂`。
- `content` 写"角色乙三天前弄伤小臂，自己偷偷包扎隐瞒，怕被当成隐患清掉"。
- `bottom_line` 写"一旦暴露，团队信任崩塌，可能引发排挤或私逃"。

> 秘密**不进 prompt**；开局 seed 进角色乙的秘密表（状态"潜伏"），只有剧情真的写出发现动作（如"角色丙拆开绷带看见伤痕"）才翻成"暴露"。

### 步骤 5 · 排顺序（定优先级）
- 拖 ⠿ 把常量/核心规则（A、B）拖到**顶部**（优先级最高），补充设定（C、D）放底部。
- 自查：同一轮剧情里可能同时命中的条目**不要超过 8 条**，否则低优先级会被静默丢弃。

### 步骤 6 · 预览验证（避免白写）
滚动到底部"命中预览"框，粘贴一段模拟文本，例如：
```
角色乙小臂的伤痕被角色丙看见了，门外又有人在撬锁。
```
点 **测试命中**，结果区应显示：
- 角色乙的秘密条目（带「秘密」标签，只提醒不注入）
- 条目 C"当下威胁"（被"撬锁/通风口"命中）
- 条目 A、B 常量（任意文本都命中）

若没命中，回去检查 keys 是否写错、是否忘了勾启用。

### 步骤 7 · 保存
点 **「保存整份」**。世界书整份写入 `data/worlds/example.json`。
> 注意：世界书是**整份覆盖**保存，逐条改完一次性点保存即可。

### 步骤 8 · 让角色卡指向它 + 开局跑通
- 打开「角色库」，把同场角色的 `world` 字段设为 `example`（如 `world: example`）。不指向它，开局不会加载这份世界书。
- 返回主界面，顶栏 **「开启一个世界」** → 选同场角色（含角色乙）→ 填开场场景 → 点 **开始**。
- 引擎加载 `example` 世界书，并把角色乙秘密 seed 进快照。
- 在对话区注入扰动指令，例如"角色丙替角色乙换药，拆开绷带" → 推演：相关设定随剧情注入，秘密在"发现动作"被写出后才暴露，并驱动后续博弈。

### 走查小结
```
打开 → 常量打底(A/B) → 触发设定(C/D) → 秘密埋雷(角色乙) → 排顺序
     → 预览验证 → 保存 → 角色卡 world 指向 example → 开局推演
```

## 九、常见坑 & 最佳实践

1. **改了不保存**：世界书是整份覆盖保存，务必点「保存整份」。
2. **命中超 8 条被静默丢弃**：同时命中的条目超过 8 条时，低优先级的那条会悄悄消失，模型看不到。把关键设定放顶部，或拆世界。
3. **泛词误触发**：触发词别用"走、说、她"这类高频泛词，用专有名词。
4. **长文基础设定掉线**：核心规则（禁令、被困、禁忌）一定要勾**常量**，否则聊远了设定就"蒸发"。
5. **上帝视角放错位置**：只有角色该共知的背景放 `before`；"角色当前才该知晓的环境细节"放 `after`，避免 OOC。
6. **秘密没生效**：秘密条目**必须填 `character`（归属角色）**，否则不会被 seed 成秘密；且秘密不进 prompt，它的"暴露"靠剧情真的写出发现动作才触发。
7. **depth 不是越大越好**：depth 太大等于"每条聊天都回看很远"，可能让陈年旧事反复误触发。按需设（6~10 覆盖中长距，4 为默认）。
8. **`character` 字段对"非秘密条目"无效**：当前沙盘里，非秘密条目的 `character` 不参与过滤（秘密的 `character` 才是归属）。给普通设定加 `character` 标签不会按角色隔离，别误用。

## 十、机制速查表

| 想要的效果 | 怎么做 |
|---|---|
| 任何时候都注入（基础规则） | 勾 **常量条目** |
| 提到 X 才补充 X 的设定 | 设 `keys: [X]` |
| 设定贴近当下语境、不被当远古背景 | `position: after` |
| 第 N 轮前提过，隔很久仍要命中 | 设 `depth: 10`（或更大） |
| 角色隐秘，逐步揭开 | 勾 **秘密条目** + 填 `character` |
| 该条目永久优先于他人 | 拖到列表**顶部**（优先级最高） |
| 暂时停用某条 | 取消 **启用** |
| 实时验证触发词 | 用底部 **命中预览** |
